## 2. 权限安全验证 ⭐ 本轮新增，优先做

> 这一节验证的是修 ISSUE-01 时引入又修掉的安全缺陷。**若这里失败，请最优先报告。**

### 2.1 计划执行不改变你的权限设置

**步骤**
1. 点击输入框底部工具栏的**盾牌图标**，选 **「计划模式（只读不改）」**（图标变为眼睛）
2. 输入：`请为 强化学习与 RLHF.md 增加一节「常见误区」，先给我计划`，等待回答完成
3. 出现「执行计划」卡片后，**先记下此刻工具栏的图标**（应为眼睛）
4. 点击 **「按此执行（重新发起一轮）」**
5. **在新一轮还在生成的过程中**，点开盾牌菜单查看

**预期**
- 第 5 步菜单中打勾的仍是 **「计划模式（只读不改）」**——执行期间你的设置**不应该**被改成别的
- 工具栏图标全程保持眼睛，不出现闪变

**❌ 失败判据**：执行期间菜单勾选项变成了「自动接受编辑」或其它 → 说明全局状态仍被改动，立即报告

### 2.2 执行完毕后设置仍是你选的那个

**步骤**
1. 承接 2.1，等新一轮彻底结束（发送键从「停止」图标变回纸飞机）
2. 点开盾牌菜单

**预期**
- 仍勾选 **「计划模式（只读不改）」**

### 2.3 双面板不串权限 ⭐ 本轮 Critical 的核心验证

**步骤**
1. `Cmd + P` → 输入 `在主编辑区打开大面板` → 回车（现在**同时开着两个** Workbuddian 面板：侧栏 + 主编辑区）
2. 在**侧栏面板**用计划模式提问，拿到计划卡片，点「按此执行」
3. **趁这一轮还在跑**，切到**主编辑区面板**，查看那里的盾牌菜单勾选项

**预期**
- 主编辑区面板的权限菜单勾选项**与你的设置一致**（计划模式），不受另一个面板正在执行的影响

**❌ 失败判据**：主面板显示的模式变成了「自动接受编辑」→ 立即报告

### 2.4 重启后设置不漂移

**步骤**
1. 完成 2.1~2.3 后，完全退出 Obsidian 再重新打开，进入 demo-vault
2. 打开聊天面板，点开盾牌菜单

**预期**
- 勾选项仍是你最后主动选择的那个（计划模式）

**❌ 失败判据**：变成了「自动接受编辑」→ 说明放宽的权限被写进了磁盘，立即报告

### 3.2 ISSUE-02 — `@` 补全的键盘操作

**注意**：交互方式与上次不同了，请严格按新方式操作。

**步骤**
1. 在输入框输入 `@`，等下拉出现（默认**第一项**带高亮：背景色 + 左侧一条土黄竖线）
2. 按 **↓** 两次 → 高亮应移到第 3 项
3. 按 **↑** 一次 → 回到第 2 项
4. 按 **回车**

**预期**
- 插入的是**当前高亮那一项**（第 2 项），输入框上方出现对应的引用 chip
- **不应该**发送消息，**不应该**只发出一个孤立的 `@`

**❌ 失败判据**：回车把 `@` 当消息发了出去／插入的不是高亮项

#### 3.2b 鼠标与键盘高亮不打架

**步骤**

**❌ 失败判据**：两项同时高亮／回车插入的不是看起来高亮的那项

#### 3.2c 中文输入法不受干扰（若环境支持中文输入）

**预期**

**❌ 失败判据**：回车插入了一个 `@[[某笔记]]`，而你只是想确认拼音候选

### 3.3 ISSUE-03 — 撤销后的按钮标签

**背景**：真凶是可访问名（`aria-label`）从未更新。**如果你通过 a11y tree / accessible name 读取按钮**（多数 GUI 自动化如此），这正是上次读到「撤销此修改」的原因。

**步骤**
1. 输入 `请把 微调与对齐.md 的第一句改写得更简洁`，等完成
2. 展开工具调用块 → 展开「改动 微调与对齐.md」
3. 点 **「撤销此修改」**
4. 分别检查按钮的**三个通道**：
   - 可见文字
   - **可访问名**（a11y tree 里的 name / `getByRole('button')` 读到的名字）
   - 鼠标悬停弹出的 tooltip

**预期**
- **三者全部**变为 **「已撤销」**
- 按钮变为不可点击、带删除线
- 右上角弹出一条 **「已撤销」** 的 Notice
- 文件内容回到修改前

**❌ 失败判据**：三个通道里任意一个仍显示「撤销此修改」→ 请明确指出是哪一个通道
