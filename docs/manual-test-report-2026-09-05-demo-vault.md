# Workbuddian demo-vault Computer Use 全功能测试报告

## 结论

本轮在真实 Obsidian UI 中完成了主要用户链路的 Computer Use 测试。聊天、Vault 文件读取、Markdown 渲染、会话管理、引用、附件选择、设置和持久化均有可见证据；但当前本机 Hermes ACP 在 Obsidian 重载后回退到轻量模式，导致工具、批准卡和真实写入链路不能完成。因此本轮不能判定“全部功能通过”，也没有把未验证项标为通过。

建议先处理 P1：停止响应、ACP/轻量模式降级可见性、主编辑区大面板命令；随后补一轮真实 CLI 登录条件下的写入/批准/撤销/附件发送验收。

本轮未发现 P0 级数据丢失、应用崩溃或静默写错；P1/P2 均已在下文给出复现证据和改进方向。

## 本轮修复与回归

## 候选 Issue（本轮未远程创建）

以下是已整理好的 issue 草案；本次只形成报告，没有向 GitHub/Harness 远程提交或关闭 issue。

已知 GitHub #6「没办法调用 skill」仍是开放问题；本轮因 ACP/CLI 回退未能在完整条件下复测，不重复开单。

### P1（已修复）：停止生成后超过 30 秒仍显示“思考中”

**复现**：发送至少 2000 字的持续输出请求，点击“停止”，等待 30 秒以上。

**实际**：停止按钮和“思考中”仍保持，之后才恢复。

**期望**：点击后立即进入“正在停止”状态；在明确超时后取消请求、回收进程并恢复输入框，展示可诊断错误。

### P1（已修复）：ACP 失败回退轻量模式时，完整能力不可用但缺少可恢复路径

**复现**：重载 Obsidian，在 Hermes ACP 初始化失败/模型接口回退条件下观察聊天面板。

**实际**：显示“轻量模式：工具/批准卡不可用”，基础文本仍可回答，但工具、批准和写入链路不可用。

**期望**：启动时展示后端健康状态、失败原因、重试/重新检测入口；能力受限时明确禁用对应操作，避免用户误以为是完整模式。

### P1（已修复）：`在主编辑区打开大面板` 执行后没有可见主面板

**复现**：命令面板执行该命令。

**实际**：命令可见，但未观察到主编辑区切换或大面板出现。

**期望**：打开/聚焦主编辑区 Workbuddian 面板；若已有面板，明确聚焦并给出可见反馈。建议增加自动化回归断言。

### P1（已修复）：发布清单与 demo-vault 清单版本漂移

**复现**：对比仓库 `manifest.json` 与 `demo-vault/.obsidian/plugins/workbuddian/manifest.json`。

**实际**：代码文件 hash 一致，但 demo-vault manifest 仍为 2.6.1，而仓库 HEAD/release 为 2.6.3。

**期望**：发布/测试 fixture 使用同一版本清单；加入 release smoke check，禁止代码与 manifest 版本不一致。

### P2（已修复）：模型按钮只显示“模型”，缺少当前模型/后端反馈

**实际**：聊天界面按钮显示为“模型”，没有稳定显示当前模型名称或降级状态。

**期望**：展示当前后端/模型；加载中、不可用、轻量模式和回退状态都应有明确文案。

### P2（已修复）：删除当前会话后，分叉标签仍残留在会话索引

**复现**：打开 `分叉 - 概括Vault笔记主题`，右键选择“删除对话”，确认删除，再搜索“分叉”。

**实际**：删除确认消失后，当前 tab 和搜索结果仍显示该分叉会话；需要重载后再确认是否只是内存列表未同步。

**期望**：删除成功后立即从 tab、搜索结果和持久化索引移除；当前会话被删除时自动切换到有效会话。

## 改进建议

1. 为后端建立显式能力状态：`ACP_READY`、`LIGHTWEIGHT`、`CLI_MISSING`、`AUTH_REQUIRED`、`FAILED`，并让工具、批准、附件发送、写入按钮按能力禁用或提示。
2. 将停止操作做成可观测状态机：`stopping`、取消确认、超时兜底、子进程回收和可重试错误；补一个 5 秒内恢复输入框的回归测试。
3. 将“主编辑区大面板”做成可断言的 UI 行为：检查 workspace leaf/view 类型、可见标题和焦点，而不是只断言命令注册成功。
4. 为 demo-vault 增加测试前快照/测试后恢复脚本，避免手工测试留下会话、置顶和草稿污染；本轮 Vault 被忽略且没有覆盖代码，但测试消息仍属于本地测试数据副作用。
5. 发布流程增加三项一致性检查：仓库与 fixture 的 `manifest.version`、关键静态文件 SHA-256、运行时 `/api/app/info`/插件版本；失败时阻止发布。
6. 扩展 e2e/人工报告协议：每项必须输出 PASS/FAIL/BLOCKED，CLI/登录缺失不得以退出码 0 伪装成功；对审批、写入、撤销、附件授权增加真实条件下的验收矩阵。
