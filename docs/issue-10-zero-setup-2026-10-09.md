# Issue #10：WorkBuddy 原账号零组件接入验收

## 结论与适用范围

`2.6.14` 在当前 macOS、WorkBuddy `5.7.7`、Obsidian `1.13.7` 的 demo-vault 中通过了无连接组件首次对话、宿主自动启动、原界面会话续聊和取消后继续对话。用户只需安装并登录 WorkBuddy，再从 Obsidian 发消息；不需要安装本地连接扩展、先在 WorkBuddy 发消息、另建账号或配置独立 API key。

这不是全功能、全平台或长期高可用验收。Windows 实机、长请求、大附件、审批卡完整 GUI 和账单额度差值仍待验证，Issue #10 保持开放。发布状态以 `2.6.14` 标签及对应 GitHub CI、Release 为准。

## 原因与修复

旧插件要求 v6 sidecar 已存在；宿主不再预热它时，安装并登录 WorkBuddy 本身仍不足以首次连接。`2.6.13` 的连接组件能够初始化 sidecar，但安装并重启的前置操作不符合零配置目标。

`2.6.14` 保留可用 sidecar 和旧版 stdio 路径；仅在缺少连接组件时，使用宿主正常 WBIPC `wb.request/http.fetch` 账号代理。握手诚实声明插件身份，不伪装内置客户端。宿主负责实际账号认证，插件不提取、复制或解密登录凭据；本地短期传输票据只用于握手，处理后清零。

插件运行 WorkBuddy 内置 CLI，使用桌面端自带运行时、插件自有本地代理和按 Vault 隔离的会话目录。宿主未运行时只正常打开已识别的安装，不关闭或重启活跃宿主。目录、文件、socket、双向认证、帧大小和请求数量均有校验；断线使当前请求失败，下一条用户消息才重新连接。清理只终止插件创建的子进程，不猜测或终止宿主任务。

Issue 最新 Windows 反馈还指出 `WorkBuddy AI` / `workbuddy-desktop-ai` 标识被旧精确判断拒绝。发布补丁同时接受这两个已知标识及原标识，并识别已知桌面可执行文件；不采用宽泛产品前缀或任意可执行文件。自定义安装目录未被自动发现时，仍需在设置指定安装内 CLI 路径。

## 原生通路限制

WorkBuddy `5.7.7` 的原生 HTTP 代理完整读取响应后才返回，不提供模型 token 的即时流式输出。单次宿主请求期限约 **50 秒**；插件原生代理的请求和响应分别限制约 **640 KiB**。大附件、长输出及超大上下文可能超限。已有 sidecar 通路继续使用原流式能力。

原生 CLI 实测返回内置的 **9 个模型**，不是桌面任务界面的完整模型集合；插件没有补造模型条目。内置 CLI 可能自行生成标题。使用宿主账号认证已验证，但没有以账单余额差额证明具体扣费归属或零额外消耗。

插件不自动重放用户 prompt，且关闭 CLI 可配置的 HTTP 重试与重试 watchdog。本地代理明确失败返回 HTTP 422，真实内置 CLI 故障探针只发出一次模型请求。CLI 自身在响应头到达前的连接失败或 Agent 恢复仍可能有另一次请求；这不是全链路绝对“至多一次”的保证。

## 验收结果

| 检查 | 结果 |
| --- | --- |
| 缺少连接组件的整链路回归 | 先复现“安装连接扩展并重启”错误，再通过真实 socket 宿主夹具、独立 CLI 子进程及生产代理完成 ACP 首条消息；不是 mock 被测代理函数。 |
| 真实内置 CLI 与生产 Native 模块 | 原账号请求完成，`end_turn`；初始化、会话、9 个模型、回复、自有 worker 清理均成功。 |
| demo-vault 无组件首次对话 | 发送前没有连接组件和存活 sidecar，精确收到 `WB_ZERO_UI_READY_1009`。 |
| 宿主未运行时自动启动 | 正常退出空闲 WorkBuddy，确认宿主进程及端点均不存在；直接在原 Obsidian 界面会话发送消息，宿主自动打开并精确回复 `WB_ZERO_AUTOSTART_1009`。没有重新登录或重载插件。 |
| 取消后继续 | 点击停止后可立即发送下一条，精确收到 `WB_ZERO_AFTER_CANCEL_1009`。停止的空回复仍显示通用“无响应，请重试”文字，尚未单独优化。 |
| GUI 持久化交叉核验 | 仅读取本测试会话，三个精确回复标记均存在；未输出完整用户设置或其他会话。 |
| 真 CLI 失败不重试探针 | 使用合成宿主，不触真实账号；HTTP 422 后返回 `refusal`，主模型请求 1 次、全部模型请求 1 次，自有 worker 清理成功。 |
| Broker 边界 | 双向认证、路径信任、取消、超时、并发、乱序响应、断线及逐帧限制通过；Windows 命名管道为模拟平台验证。 |

初次 UI ASCII 输入曾因自动操作中文输入缺失而调用 Read 读取当前 demo 笔记；之后改用粘贴并核对完整指令再发送。因此不把所有试验都记成“零工具调用”，也不将这一条读取等同全工具权限验收。

## 本机改动与回退

没有修改 WorkBuddy 安装包、登录存储或全局配置。demo-vault 旧插件三文件备份在 `/tmp/workbuddian-native-demo.WrmqET`；测试时移出的本插件连接扩展已经原样恢复。新通路自己的持久化会话位于宿主配置目录的 `workbuddian/<Vault 路径 SHA-256>`，不合并或复制宿主会话。

需要回退时，停用 demo 插件并还原备份的 `main.js`、`manifest.json`、`styles.css`，再启用。已安装的可选连接组件保留，未删除厂商或其他插件资源。用户原有 `CLAUDE.md` 改动不属于此次提交。
