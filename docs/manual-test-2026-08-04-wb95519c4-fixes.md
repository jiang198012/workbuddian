## 本轮新增的根因结论（来自 acp-probe 探针，指导预期判定）

1. **CLI 的流式事件与模型上下文跟随"最近 new/load 的会话"，而不是 prompt 请求里的 sessionId**（reactivate2 探针实锤：A 的 prompt 的 54 个 chunk 全部打到标题会话 T 名下，回答也用的是 T 的上下文）。这是 F1（自动标题后无响应）与 F6（fork 后原会话失效）的共同根因。
2. **修复手段**：prompt 前若本会话不是活动会话，先重发 `session/load` 激活（titlefix 探针验证：激活后事件归属与上下文都正确）。**副作用属预期**：切换到另一会话后的第一条消息会先跑一遍历史回放，开始流式比之前慢几秒。
3. **`set_mode`/`set_config_option` 同样跟随活动指针**（configroute 探针实锤：B 激活时对 A set_mode 无效）。修复：灌配置前先激活目标会话。
4. **`session/load(不存在的 uuid)` 会成功**（幽灵会话），属 CLI 行为，插件不依赖其失败。
