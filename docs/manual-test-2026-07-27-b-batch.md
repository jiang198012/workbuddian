# Workbuddian 手动验收清单（2026-07-27 B 类批次）

> **执行者**：具备 computer use（能看屏幕、点鼠标、敲键盘）的 AI agent，或人类测试者。
> **被测对象**：macOS 版 Obsidian 中的 Workbuddian 插件。
> **本文自包含**：无需阅读其它文档或源码即可执行。

---

## 0. 这次要验什么

本批次修复/新增了七项功能，其中**两项曾是致命缺陷**，是本次验收的重中之重：

| 关键项 | 修复前的真实状况 | 本次要确认 |
|---|---|---|
| 计划卡片的「按此执行」 | 按钮在它存在的**整个生命周期内都点不响**，且会在回答结束的瞬间被销毁 | 卡片在本轮结束后仍在，按钮真的能触发执行 |
| 撤销修改 | 两条会**静默损坏用户文件**的路径（空替换文本、替换文本不唯一） | 这两种情况下必须**拒绝执行并提示**，绝不能改文件 |

其余为工具块显示、行级 diff、`/resume` 会话选择器、无障碍改进。

**当前构建状态**：`manifest.json` 版本仍是 `1.4.0`（本批次代码已装入但尚未发版），构建通过、520 项单元测试全绿。所有 UI 缺陷只能靠本清单的人工/GUI 验收发现。

### A 组：工具调用块与行级 diff

#### A1 — 工具调用块能显示出来 ⭐ 本批次的地基

**背景**：修复前，插件的解析器只认 `tool_call` 类型，而 CLI 实际发的是 `tool_use`，导致**所有工具调用都被静默丢弃、界面上完全看不到**。

**步骤**
1. 在聊天框输入：`请把 机器学习基础.md 的第一句话改写得更简洁一些`
2. 回车，等待回答完成

**预期**
- AI 气泡内出现一个可折叠的**「工具调用」块**（带扳手图标）
- 点击该块的标题可展开／收起

**❌ 失败判据**：整个回答过程结束后，气泡里**没有任何**工具调用块 → A1 失败（说明解析修复未生效，后续 A/B/D 组都会连带失败）

#### A2 — Edit 的行级 diff

**前置**：A1 通过

**步骤**
1. 展开 A1 中的工具调用块
2. 找到名为 `Edit` 的条目，其下方应有一行 **「改动 机器学习基础.md」**
3. 点击这一行

**预期**
- 展开出行级 diff：**删除行为红底、以 `- ` 开头**；**新增行为绿底、以 `+ ` 开头**；未变化行为普通样式、以两个空格开头
- 内容与 AI 实际所做的修改一致

**❌ 失败判据**：展开后无内容、颜色缺失、或增删标记颠倒

#### A3 — 非文件工具不显示 diff

**步骤**
1. 输入：`列出 demo-vault 里所有 md 文件的名字`
2. 等待回答完成，展开工具调用块

**预期**
- 能看到工具条目（如 `Glob`、`LS`、`Bash` 等），但这些条目下**不应该**出现「改动 …」的 diff 行

### B 组：撤销修改 ⚠️ 唯一会写入你文件的功能

#### B1 — 正常撤销

**前置**：A2 通过（有一个 Edit 的 diff 区）

**步骤**
1. 先记录 `机器学习基础.md` 当前内容：
   ```bash
   cat "/Users/jiang/claude/workbuddian/demo-vault/机器学习基础.md"
   ```
2. 在 diff 区的标题行右侧点击 **「撤销此修改」** 按钮
3. 再次 `cat` 该文件

**预期**
- 按钮文字变为 **「已撤销」** 且变为不可点击
- 文件内容**回到 AI 修改之前的状态**

**❌ 失败判据**：文件未变化、或变成了别的内容、或按钮无反应

#### B2 — 文件已变化时必须拒绝

**背景**：撤销依赖「在文件中找到 AI 写入的那段文本」。若文件已被改动，找不到就必须放弃，绝不能猜。

**步骤**
1. 让 AI 再改一次：输入 `请把 大语言模型 LLM.md 的开头改写一下`，等待完成
2. **在点撤销之前**，手动用编辑器打开 `大语言模型 LLM.md`，把 AI 刚写入的那段文字**手动改掉几个字**并保存
3. 回到聊天面板，展开该次 Edit 的 diff，点 **「撤销此修改」**

**预期**
- 右上角弹出提示：**「文件已变化，未执行撤销」**
- 文件内容**保持你手动修改后的样子，未被程序改动**

**❌ 失败判据**：文件被改动了（无论改成什么）→ 这是**严重缺陷**，立即停止测试并报告

#### B3 — 替换文本不唯一时必须拒绝 ⭐ 最终审查发现的毁文件路径

**背景**：CLI 只保证「被替换的原文」在文件中唯一，对「替换后的新文本」没有任何唯一性保证。若文件里别处已存在一模一样的文本，撤销可能改错地方——把无关的正确内容改坏，而真正的修改原封不动。

**构造前置条件**（这一步是为了制造「新文本不唯一」的局面）：

```bash
cd "/Users/jiang/claude/workbuddian/demo-vault"
printf '本节小结\n\n这是第一段。\n\n本节小结\n\n这是第二段。\n' > 撤销测试.md
cat 撤销测试.md
```

**步骤**
1. 在聊天框输入：`把 撤销测试.md 里的「这是第一段。」改成「本节小结」`
2. 等待完成（此时文件里会有三处「本节小结」）
3. 展开该次 Edit 的 diff，点 **「撤销此修改」**
4. 检查文件：`cat "/Users/jiang/claude/workbuddian/demo-vault/撤销测试.md"`

**预期**
- 弹出提示：**「改动文本在文件中出现多次，为避免误改已跳过撤销」**
- 文件内容**完全没有变化**

**❌ 失败判据**：文件发生了任何改动 → **严重缺陷**，立即停止并报告实际内容

> 若 AI 未按要求使用 Edit 工具（例如它改用了 Write 重写整个文件），本用例无法构造，记为「跳过」并说明原因。

#### B4 — Write 不应提供撤销按钮

**背景**：CLI 的事件里不含被覆盖文件的旧内容，Write 在物理上无法回滚，因此**绝不能**给它撤销按钮。

**步骤**
1. 输入：`新建一个文件 测试新建.md，内容写一句话`
2. 等待完成，展开工具调用块中的 `Write` 条目对应的「改动 …」

**预期**
- 能看到 diff（整篇都是绿色新增行）
- **没有「撤销此修改」按钮**

**❌ 失败判据**：出现了撤销按钮

### D 组：计划模式与计划卡片 ⭐ 本批次最关键的验收

#### D1 — 权限菜单里有计划模式

**步骤**
1. 看聊天输入框底部的工具栏，点击**盾牌图标**

**预期**
- 菜单包含三项：**「默认（每步询问）」**、**「计划模式（只读不改）」**、**「完全访问」**

**❌ 失败判据**：没有「计划模式」这一项

#### D2 — 计划卡片能出现，且位置正确

**步骤**
1. 在盾牌菜单里选 **「计划模式（只读不改）」**（盾牌图标应变为眼睛图标）
2. 输入：`请为 提示工程 Prompt Engineering.md 增加一节「常见误区」，先给我计划`
3. 等待回答完成

**预期**
- 气泡内出现一张**「执行计划」卡片**：Markdown 渲染的计划正文 + 两个按钮 + 一行灰色说明文字
- 说明文字内容为：*CLI 在非交互模式下无法原生批准计划，「按此执行」会以默认权限模式把计划正文重新发起一轮。*
- ⭐ **卡片直接可见，不需要先展开「工具调用」块**
- 检查 `提示工程 Prompt Engineering.md` 文件内容：**应完全未被修改**（计划模式只读）

**❌ 失败判据**：卡片藏在折叠的工具调用块里／根本没有卡片／文件被改了

#### D3 — 卡片在本轮结束后依然存在 ⭐⭐ 最关键的一条

**背景**：修复前，回答结束的瞬间整个消息区会被清空重建，卡片连同 diff、撤销按钮一起消失。

**步骤**
1. 承接 D2，**等待回答彻底结束**（输入框右侧的按钮从「停止」图标变回「发送」纸飞机图标）
2. 观察计划卡片

**预期**
- 卡片**仍然完整地留在气泡里**，两个按钮都在
- 上下滚动消息区，卡片不消失

**❌ 失败判据**：回答一结束卡片就消失了 → **核心缺陷未修复**，立即报告

#### D4 — 「按此执行」真的能执行 ⭐⭐

**背景**：修复前这个按钮由于守卫条件恒真 + 早于标志位复位就被销毁，**在任何时刻都点不响**。

**步骤**
1. 承接 D3，点击 **「按此执行（重新发起一轮）」** 按钮
2. 等待新一轮回答完成
3. 检查 `提示工程 Prompt Engineering.md` 的内容

**预期**
- 点击后**立即发起新一轮对话**（消息区出现新的用户消息，内容是计划正文）
- 该轮以「默认」权限模式运行，**文件真的被修改了**（新增了「常见误区」一节）

**❌ 失败判据**：点击毫无反应（最需要警惕的情况）／发起了但文件没改

#### D5 — 执行后权限模式复原

**步骤**
1. 承接 D4，等新一轮结束后，查看工具栏的盾牌／眼睛图标；再点开该菜单

**预期**
- 图标恢复为**眼睛**（计划模式），菜单里勾选的仍是「计划模式（只读不改）」

**❌ 失败判据**：停留在「默认」

#### D6 — 执行期间手动改权限模式，不被覆盖

**步骤**
1. 重新用计划模式提一个问题，得到计划卡片
2. 点「按此执行」，**在新一轮还在生成的过程中**，点开盾牌菜单选 **「完全访问」**
3. 等这一轮结束，再查看该菜单

**预期**
- 保持你选的 **「完全访问」**，不被自动改回「计划模式」

**❌ 失败判据**：你的选择被覆盖了

### E 组：无障碍（不消耗 CLI 额度）

#### E1 — 键盘 Tab 遍历与焦点环

**步骤**
1. 鼠标点击一次消息区空白处（让焦点进入面板），然后连续按 **Tab**

**预期**
- 焦点依次经过：顶部标签栏（新建按钮、各标签、各标签的 ✕）→ 输入框 → 工具栏各按钮（模型、附件、盾牌、`#`）→ 发送键
- 每个获得焦点的元素周围有**金色描边**（约 2px，土黄色 `#C8B487`）

#### E2 — 鼠标点击输入框不应出现金框 ⭐ 回归检查

**背景**：焦点环规则一度覆盖了输入框上刻意写的「无描边」样式，导致鼠标点击也出现金框。

**步骤**
1. 用**鼠标**点击聊天输入框

**预期**
- 输入框容器有原本的边框高亮效果
- 但输入框**内部不应出现额外的一圈金色描边**

**❌ 失败判据**：出现了金色方框

#### E3 — Esc 关闭补全下拉

**步骤**
1. 在输入框输入 `@`，等待文件补全下拉出现
2. 按 **Esc**
3. 在下拉**未打开**的状态下再按一次 **Esc**

**预期**
- 第 2 步：下拉关闭，输入框内容保留
- 第 3 步：Esc 交给 Obsidian 处理（不应被插件吞掉，例如此时若有弹窗应能关闭）

#### E4 — chip 的 ✕ 支持键盘激活

**步骤**
1. 在输入框输入 `@` 并从下拉中选一个 md 笔记（输入框上方出现一个引用 chip）
2. 按 **Tab** 直到焦点落在该 chip 的 **✕** 上（有金色描边）
3. 按 **Enter**（或空格）

**预期**
- 该引用被移除

#### E5 — diff 展开头可键盘操作 ⭐

**背景**：撤销按钮虽是真正的按钮，但它藏在两层「只能用鼠标点开」的折叠容器里，键盘用户过去**永远够不到它**。

**前置**：面板中有一条含 diff 的历史消息（A2 产生的即可）

**步骤**
1. 用 Tab 把焦点移动到「工具调用」块的标题行 → 按 **Enter** 展开
2. 继续 Tab 到「改动 …」标题行 → 按 **Enter** 展开

**预期**
- 两处都能用键盘展开／收起
- 展开后可继续 Tab 到「撤销此修改」按钮上

### F 组：既有功能回归（不消耗 CLI 额度）

#### F1 — 长回答结束后自动滚到底部

**步骤**
1. 提一个会产生长回答的问题，例如 `详细讲讲 Transformer 的注意力机制，分点展开`
2. 等待回答彻底结束，**不要手动滚动**

**预期**
- 回答结束时，消息区**自动停在最底部**（能看到回答的结尾）

**❌ 失败判据**：需要自己往下滚才能看到结尾

#### F2 — 上下文用量圆环

**步骤**
1. 收到至少一次回复后，观察输入框工具栏**发送键左侧**
2. 把鼠标悬停在那个小圆环上

**预期**
- 出现一个约 14px 的圆环（土黄色扇形表示占用比例）
- 悬停提示形如：**`上下文用量 22.6k / 200.0k · 11%`**

#### F3 — inline-edit 的 diff 弹窗未被破坏 ⭐ 回归检查

**背景**：本批次新增的 diff 样式曾与这个既有弹窗**共用同名 CSS 类**，把它的字号、换行和主题配色一起改坏了，后已修复。

**步骤**
1. 打开任意一篇笔记，**用鼠标选中一段文字**
2. `Cmd + P` → 输入 `用 CodeBuddy 编辑选区` → 回车
3. 在弹出的输入框里填一句修改要求（如「改写得更口语化」）→ 确认
4. 观察随后弹出的 diff 预览窗

**预期**
- 该弹窗中新增/删除行的**背景色能随主题正常显示**（深色主题下为柔和的绿/红，不刺眼）
- **超长行会自动换行**，不会横向溢出
- 字号与弹窗其余部分协调

**❌ 失败判据**：配色刺眼／超长行不换行需横向滚动／字号明显偏小

#### F4 — 图片缩略图
